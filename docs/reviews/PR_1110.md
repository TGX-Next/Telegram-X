# Forum topic integration review

Integrates [TGX-Android/Telegram-X#1110](https://github.com/TGX-Android/Telegram-X/pull/1110),
head `361a0adaafa48153dfe52fab3f05097685d2cb03`, into TGX-Next main at
`90c4b811be6ab4202c9c5b7d9234abcef22831e2`.

The supported target remains `latest`, Android 13+ and ARM64.

## Integration and corrections

- Resolve conflicts in chat previews, swipe navigation, notification rendering, message sending,
  and shared media. Preserve the fork's batched chat updates, cached date labels, date-change
  listener, HD media overload, and shared-result imports.
- Remove the notification-content feature flag already deleted by the fork. The initial Java
  compilation reproduced the unresolved-symbol failure.
- Keep notification grouping within the same chat, topic, and sender. Previously, simultaneous
  forwarded messages in different topics could collapse into one notification entry. Two focused
  regression tests failed before the fix and passed afterward; same-topic grouping stayed valid.
  Permanent tests also cover different chats and senders.
- Remove pre-Android-13 fallback branches introduced by the PR.

## Validation

- `:app:assembleLatestDebug -Pabi=arm64`: passed; generated the ARM64 debug APK.
- `:app:testLatestDebugUnitTest`: 585 tests, zero failures, errors, or skips, including five
  permanent notification-grouping regressions and the imported topic checks.
- `checkMinSdk`: passed.
- `:app:lintLatestDebug`: passed with zero errors; 19 warnings on unchanged lines and
  17 existing baseline-filtered warnings. The 28 obsolete API guards introduced by the PR were
  removed.

The final run used JDK 25, `--max-workers=2`, and
`--init-script tests/unit/checks/forum-checks.init.gradle` to include the author's Java checks.
An earlier run under concurrent native compilation failed the existing
`DequeSerialQueueTest.dueDelayedWorkRunsBeforeWorkSentAfterItsTime` timing test. The unchanged
suite passed on the final run; its 10 ms scheduling assumption remains sensitive to load.

The author's change-specific JVM checks were obtained from
`26394b88b2f0fe640d206446fc57d45924fd7955` and restored into ignored `tests/unit/checks`.
Their InputTextQuote fixture was adapted to the fork's additional rich-text constructor argument.
They are supplementary checks, not newly committed production tests. The local run log is in
`tests/unit/checks/pr1110-results/validation.log` (ignored).

## Known dependency and coverage limits

The pinned TDLib source is `4c6377aa7386c39217878a9a56d581922ad37ca4`. It does not include
[tdlib/td#3766](https://github.com/tdlib/td/pull/3766), which remains a separate pending change.
The client integration does not resolve that dependency's native notification policy, persisted
notification counts, or per-topic read/count reconciliation defects. A successful JVM run does
not validate these server/native behaviors. The dependency also changes database persistence
and explicitly does not support downgrading a database written by its newer implementation.

No Android device was connected. Forum screens, real-account sending, notification delivery,
accessibility, animation/frame performance, screenshots, and device integration tests were not
validated in this review. Historical recordings attached to the original PR are not evidence for
this fork's current build. Review focused on merge compatibility, topic identity, notification
isolation, and the supplied regression suites; it is not an exhaustive audit of all new UI code.
